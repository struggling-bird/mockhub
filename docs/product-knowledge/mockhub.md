# MockHub 产品知识

MockHub 是一款面向研发与测试团队的接口模拟与代理管理平台。它在 Postman 等传统接口调试工具的基础上，强化团队协作、场景化接口管理与自动化代理能力，覆盖本地开发、联调和回归测试流程。

## 核心能力

- 接口 Mock 管理：支持静态 JSON、动态脚本和真实代理模式。
- 项目管理：按项目隔离接口、Mock Key、代理配置和团队成员，并通过项目成员角色控制协作访问。
- 代理网关：通过统一网关入口转发或模拟接口请求，并支持项目级代理分组按正则、优先级和模式影响网关策略。
- 公共资产：集中维护基础 URL、错误码、枚举值和共享配置，并为 Mock 脚本、真实代理、接口定义和团队协作提供可复用上下文。
- 团队协作：支持项目内置角色与自定义角色，成员可按角色权限查看或维护项目、接口与公共资产。

## 目标用户

- 后端工程师：在服务未完全实现时提供稳定 Mock 接口，并通过脚本模拟异常或边界场景。
- 前端与移动端工程师：在后端不可用或不稳定时独立完成开发与联调。
- 测试工程师：沉淀可复用响应场景，并支撑自动化测试。

## 典型场景

- 前端先行开发：通过 MockHub 维护接口定义与响应，让前端在统一网关下开发。
- 线上问题复现：使用代理和脚本模式模拟特定错误响应、慢查询或边界返回。
- 测试场景编排：围绕接口响应、错误码、公共资产和项目配置构建可复用测试场景。

## 代理规则分组

- 代理规则按项目维护，支持正则匹配请求路径、优先级排序、启停和自动捕获配置。
- Mock 模式优先使用已存在接口的静态或脚本 Mock；接口不存在时返回明确未命中响应，不隐式代理到上游。
- Proxy 模式优先使用分组目标地址转发请求，适合按业务路径拆分不同上游服务。
- Hybrid 模式保留接口级 Mock/Proxy 配置，接口不存在时可通过分组或项目级代理自动学习接口定义。

## 团队成员与权限

- Owner：项目创建者，拥有项目、成员、接口和公共资产完整管理权限。
- Admin：可管理项目成员、编辑项目配置、维护接口和公共资产。
- Editor：可维护接口和公共资产，但不可管理成员或删除项目。
- Viewer：可查看项目、接口、公共资产和团队成员列表，不可执行写操作。
- Owner 可在 Team 页面维护项目角色；Owner 自身固定全权限不可修改。
- Admin、Editor、Viewer 以及自定义角色可编辑名称、描述和细粒度权限，成员邀请与成员角色调整均读取项目角色定义。
- 权限粒度覆盖项目、接口、公共资产、团队成员和角色权限管理，后端按具体 permission key 执行访问控制。
- 成员邀请支持任意合法邮箱；未注册用户可通过邀请链接注册，注册完成后自动加入被邀请项目。
- 被邀请用户注册时，邮箱和公司名称由邀请上下文默认填充并锁定；后端以邀请 token 解析出的邮箱和组织归属为准。
- 邀请会生成邀请消息和链接，前端自动复制，并在 Team 页面展示待接受邀请。

## 公共资产价值

- 对接口 Mock：脚本 Mock 可复用错误码、枚举值、共享 JSON 配置，减少每个接口重复维护常量。
- 对真实代理：Base URL 已进入 API 管理的 Proxy 目标地址候选，降低重复输入和环境切换成本。
- 对接口定义：枚举、错误码和共享 Schema 可作为参数、响应结构和测试场景的项目级参考。
- 对团队协作：公共资产把散落在接口、脚本和代理规则中的团队约定沉淀为统一项目资产，降低协作偏差。
- 对自动化沉淀：系统会基于代理配置、请求日志、接口参数、响应结构和静态 Mock 识别候选 Base URL、业务响应码、枚举集合和通用响应结构，先生成建议资产，再由用户查看详情、确认或忽略，确认后再转为正式资产。
